# Roadmap

The project is functional and under active development. Preserve working components.

1. Validate the new one-command workflow on disposable clean Arch, CachyOS and
   EndeavourOS LXQt/X11/Openbox installations: missing packages, install/repeat,
   normal login, scoped update, custom preferences, conflicts, removal and undo.
   Only then consider a stable tag/channel. Record exact versions and results.
2. Resolve physical NVIDIA display verification mismatch using already designed
   bounded phase/property diagnostics from a separately authorized hardware action.
   Preserve external-change protection; never claim prior manual restoration was
   automatic rollback. Do not request speculative hardware retests.
3. Broaden first native-profile recovery boundaries and
   broaden shortcut/layout adapters, including custom XDG roots, multiple panels
   and explicit Alt+F1 integration. Do not silently normalize personal settings.
   Completed-step recovery preserves a later multi-panel stock layout. First-time
   `profile.py prepare --panel` now supports explicit selection in bounded standard
   profiles through setup and deploy/bootstrap, with recorded choice and interrupted
   first-stage recovery. Optional Alt+F1 deployment now has explicit custom replacement,
   conservative whole-file ownership, recovery and exact undo; activation remains
   unverified. Broader layout/XDG and shortcut-format adapters remain open.
4. Expand real notifier/XEmbed/application, accessibility, mixed-DPI and long-session
   acceptance without adding a mandatory compositor or extra polling/indexing.
5. Continue Windows 7/Open-Shell and screenshot parity from the detailed inventories.
   Keep optional clipboard/video cost independent of the core. Lock-screen artwork
   remains a design-only experiment; authentication stays with the existing locker.
6. Owner review of bundled artwork provenance and distribution terms; preserve
   original code/component license notices independently.

The [existing detailed roadmap](roadmap.md), [parity inventory](open-shell-parity.md),
[lock-screen design](animated-lock-screen-design.md) and [STATUS](STATUS.md) provide
component detail. Search, folder cascades, portable preferences and display controls
are implemented; broader parity, portability acceptance and hardware recovery are
not complete. Future version support must be earned through adapters and tests.
